## 구현 내용

- `BSTNode`: `data`, `left`, `right`
- `BinarySearchTree`
  - 재귀: `search`/`_search`(bool 반환), `insert`/`_insert`(중복 무시), `delete`/`_delete`, `inorder`, `height`, `count_nodes`
  - 삭제 3케이스: 리프 → None, 자식 1개 → 자식 반환, 자식 2개 → 오른쪽 서브트리 최솟값(중위 후속자) 복사 후 후속자 재귀 삭제
  - 반복(성능 실험용): `insert_iterative`, `search_iterative`, `height_iterative`(스택에 (노드, 깊이))
- 실험: `build_for_experiment`(키 `0..n-1`, 무작위는 고정 시드 7로 shuffle), `timed_search`(워밍업 + `perf_counter` 5회 중앙값)
- 규약: 높이는 간선 기준(빈 트리 -1, 리프 0), 중복 삽입 무시, 없는 값 삭제는 변화 없음

## 실행 결과 (노트북 전체 실행, 모든 assert 통과)

로직 테스트: 20 → 30 → 70 순차 삭제, 루트 50 삭제(후속자 60 승격), 후속자의 오른쪽 자식 65 재연결, 빈 트리·단일 노드, 중복·없는 값, 고정 시드 200회 혼합 연산을 Python `set`과 대조.

|n|최소 가능 높이|무작위 삽입 높이|정렬 삽입 높이|
|---|---|---|---|
|100|6|12|99|
|1000|9|24|999|
|10000|13|29|9999|

탐색 시간(n=1000, 같은 대상 키 1000개, 5회 중앙값, Apple M1 / Python 3.14):
무작위 트리 0.000374s, 정렬 삽입 트리 0.010803s → 약 28.86배.

## 분석 요약

정렬 순서로 삽입하면 모든 노드가 오른쪽 자식으로만 이어져 높이가 n−1이 되고 탐색이 O(n)으로 떨어진다. 무작위 순서는 최소 높이의 2~3배 수준(O(log n))에 머물지만 균형이 보장되는 것은 아니다. 균형을 보장하려면 AVL, Red-Black 같은 자가 균형 트리가 필요하다. 자세한 내용은 노트북의 "분석 작성란" 참고.
